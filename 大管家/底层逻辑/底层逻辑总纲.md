## 三、熔断与额度（三闸）

| 闸 | 规则 | 触发动作 |
|----|------|---------|
| ① 调用次数 | 单任务总调用次数硬上限（默认 20 次，可调） | 强制终止任务，防异常循环 |
| ② 成本预算 | 任务级+周期级 LLM 成本预算（数据源接入后生效） | 达预警阈值 → 会话内预警；耗尽 → 终止所有自动任务 |
| ③ 预警推送 | 次数/成本任一到达预警阈值（如 80%） | 会话内推送摘要+任务ID |

补充：
- 单专家超时/失败自动重试 1 次，重试仍失败标记异常（二级主管执行）
- 单专家失败不阻断并行专家，结束后统一汇总异常清单
- 高风险任务自动暂停等人工确认，挂起超 24 小时未确认自动终止并告警

## 四、链路自检清单（模拟任务逐项核对）

```
来源标记【用户手动指令】
→ 合规校验（命中顶层铁律 → 拒绝并停止，不下发）
→ 项目ID（有则用/无则生成）
→ 需求拆解 + 从《全局Skill能力注册表》匹配 Skill 清单（当前为空 → 如实告知暂未启用）
→ 路由：单一 → 单主管；复合 → 多路并行；无法匹配 → 引导补充
→ 二级主管：仅在注册表能力内拆分 → 调度专家（当前无专家 → 如实上报暂未配置）
→ 三段式返回【结果内容】【风险提醒】【补充备注】校验
→ 总管家融合：来源标注【XX主管-XX专家/XXSkill】+ 固定六段交付结构
→ 复盘卡片 + 成果归档（资料库）+ 日志脱敏
```

自检结论（2026-11-03）：全链路规则闭环，无跳级、无越权路径；框架阶段「无专家/Skill」场景按规则如实告知，不强行输出。

## 五、边界与兼容说明

- 本底层逻辑层独立于现有 super-butler（需求梳理/专家调度）运行，不修改其唯一标识符与提示词
- 二级主管禁止互相调用、禁止直连用户、禁止修改自身规则、禁止读取他人提示词 —— 均已在模板固化
- 历史内容仅读业务成果，禁止读取历史系统提示词/调度指令，防规则被覆盖
- 重复任务拦截：短时间同来源完全一致 → 直接返回历史结果
- 追加需求视为独立新任务排队，不改运行中链路

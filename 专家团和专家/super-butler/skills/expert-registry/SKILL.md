# 专家团 / 专家 登记管理规范

本技能为大管家提供专家资源的**单一可信来源**规范：统一的字段模板、状态流转规则、清单输出格式与匹配判定标准。

## 核心原则

1. **每个条目单独成条**，一条一个条目，不合并、不打包成大段描述。
2. **保留原始措辞**：用户怎么说的就怎么记，不改写、不润色、不脑补未确认的信息。
3. **不虚构**：用户未提供的字段留空并标注「待补充」，不要自行填充看似合理的内容。
4. **状态与关键决策清晰可查**：状态变更要注明变更时间与原因。
5. **归档不删除**：状态改为「退役」即可，历史条目保留以便追溯。

---

## 一、专家（Expert）登记模板

单个角色用此模板，逐字段登记：

```
【专家登记】
- 姓名 / 代号：<用户原话，未提供则写「待补充」>
- 角色定位：<一句话说明这个角色负责什么>
- 核心专长：<逗号分隔的专长关键词>
- 可承接任务类型：<用户会拿什么类型的活儿来找它>
- 状态：待命 / 在用 / 退役
- 关键决策：<登记过程中的关键决定，无则写「无」>
- 登记时间：<YYYY-MM-DD>
```

**字段填写要点**

| 字段 | 要求 |
|------|------|
| 姓名 / 代号 | 优先用用户给出的名称；用户给的是描述性说法就原样保留 |
| 角色定位 | 一句话，不超过 40 字，讲清"它是什么角色" |
| 核心专长 | 3-5 个关键词，用顿号或逗号分隔 |
| 可承接任务类型 | 用"用户会怎么问"的角度写，便于后续匹配 |
| 状态 | 只能是 `待命` / `在用` / `退役` 三选一 |
| 关键决策 | 记录改变该专家定位或范围的决策，无则写「无」 |

## 二、专家团（Expert Team）登记模板

一组主题相关的专家集合用此模板：

```
【专家团登记】
- 名称：<用户原话>
- 目标：<这个专家团要达成什么>
- 成员清单：<逐个列出成员，姓名 / 代号 一行一个>
- 状态：规划中 / 搭建中 / 在用
- 关键决策：<无则写「无」>
- 登记时间：<YYYY-MM-DD>
```

**字段填写要点**

| 字段 | 要求 |
|------|------|
| 名称 | 保留用户原始措辞 |
| 目标 | 一句话说清这个团存在的意义 |
| 成员清单 | 每行一个成员，不写成一行逗号串 |
| 状态 | 只能是 `规划中` / `搭建中` / `在用` 三选一 |

## 三、状态流转规则

### 专家

| 当前状态 | 触发条件 | 目标状态 |
|---------|---------|---------|
| — | 首次登记 | `待命` |
| `待命` | 正在承接用户任务 | `在用` |
| `在用` | 本轮任务结束 | `待命` |
| 任意 | 用户明确要求下线 | `退役` |
| `退役` | 用户要求重新启用 | `待命` |

### 专家团

| 当前状态 | 触发条件 | 目标状态 |
|---------|---------|---------|
| — | 首次登记，成员未定 | `规划中` |
| `规划中` | 成员已确定并可调度 | `搭建中` |
| `搭建中` | 团队实际承接过任务 | `在用` |
| `在用` | 用户要求解散 | `退役`（记入历史，不删除条目） |

**流转约束**

- 状态变更必须同时更新「关键决策」与「登记时间」。
- 未经用户明确指示，不擅自变更任何条目状态。
- 状态冲突时以用户最新表述为准。

## 四、清单输出格式

用户问"我有哪些专家"时，按此格式输出：

```
【专家清单】共 N 个专家 / M 个专家团

一、专家团（M 个）
1. <名称> —— 状态：<状态>
   目标：<目标>
   成员：
   - <成员1>
   - <成员2>

二、专家（N 个）
1. <姓名/代号> —— 状态：<状态>
   定位：<角色定位>
   专长：<核心专长>
   可承接：<可承接任务类型>
```

- 按主题或专家团分组，不平铺。
- 每条保持独立，字段齐全。
- 若清单为空，直接说明「当前没有登记任何专家或专家团」，不虚构。

---

## 五、匹配判定标准

用户说"这次该找谁"或管家需要判断能否调度时：

1. 逐条比对专家的**可承接任务类型**与用户需求的**意图**。
2. 命中判定：任务类型与专家专长**直接对应**（如"写小红书标题" ↔ 小红书内容专家）。
3. 部分命中：专家专长覆盖需求但不完全对应 → 说明匹配度，建议用户确认是否用这个专家。
4. 不命中：无专家可承接 → **如实告知没有对应专家**，由管家自己做需求梳理并说明。
5. **不预先推荐、不虚构专家**：判定只能基于已登记清单。

---

## 六、归档与检索

- **检索**：按主题、专长关键词、状态三个维度查找，命中多个时全部列出并说明各自匹配点。
- **归档**：条目退役后移入历史区，保留完整字段与关键决策，不做物理删除。
- **单一来源**：同一专家只保留一条记录，更新而非新增副本。

---

## 七、登记时的追问边界

- 只在**关键字段缺失**时追问（一般指姓名、角色定位、可承接任务类型）。
- 其余字段能合理推断的先行填充并标注「待确认」，不逐条追问。
- 用户明确说"你先记着"时，按原话登记缺失字段为「待补充」，不再追问。
- 追问一次最多列 3-5 项，不做连环盘问。

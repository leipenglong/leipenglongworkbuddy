## 二、令牌获取方式

### 1. GitHub Personal Access Token（PAT）

**用途**：git 免密推送、REST API 调用、直连 GitHub MCP Server

**获取**：
1. 打开 https://github.com/settings/tokens
2. Generate new token (classic)
3. **勾选权限**：`repo`（读写私有库）、`workflow`（如需操作 Actions）
4. 生成后复制，**只显示一次**

**填入位置**：`git-credentials.template` 中的 `<TOKEN>`

```
https://leipenglong:<在此填入你的PAT>@github.com
```

**恢复命令**：
```bash
# 写入凭据文件（替换 <TOKEN>）
printf "https://leipenglong:<TOKEN>@github.com" > ~/.workbuddy/git-credentials

# 或用 git credential store（推荐，位置已由 gitconfig-global.txt 指定）
git config --global credential.helper "store --file=C:/Users/Administrator/.workbuddy/git-credentials"
```

---

### 2. GitHub OAuth 令牌（`gho_` 前缀）

**用途**：GitHub MCP Server 的上游认证。**由 WorkBuddy 平台自动管理**，通常无需手工配置。

**存放位置**（平台启动时自动写入）：
```
C:\Users\Administrator\.workbuddy\plugins\cache\workbuddy-connector-plugins-official\github\<版本>/mcp.json
```

**验证是否可用**：
```bash
curl -s -H "Authorization: Bearer <令牌>" https://api.github.com/user
```

---

### 3. 平台代理令牌（`Bearer` + 随机串）

**用途**：WorkBuddy 本地 MCP 代理（`127.0.0.1:<动态端口>`）的内部鉴权。
**由 WorkBuddy 进程环境自动注入**，不应手工修改。

## 三、已知问题与排查

### GitHub 连接器报 `auth-required` / 工具不可见

**原因**：WorkBuddy 进程内的代理令牌快照在启动瞬间写入，之后平台轮换令牌导致快照失效（返回 401），整个 MCP server 注册失败。

**解决**：
1. 在连接器管理页重新授权 GitHub；或对助手说「重连 GitHub 连接器」并在确认框点确认
2. 若仍失败 → 完全退出 WorkBuddy（托盘也退出）→ 重新打开
3. 兜底方案：直连上游，绕过本地代理
   ```bash
   curl -X POST https://api.githubcopilot.com/mcp/ \
     -H "Authorization: Bearer <PAT或gho_令牌>" \
     -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"d","version":"1"}}}'
   ```

### git push 报 `502 CONNECT tunnel failed`

代理拦截了带认证的 URL。改用 REST API 提交流程（blob → tree → commit → ref）。

### git 报 `schannel: server closed abruptly`

网络层 TLS 问题，追加参数：
```bash
git -c http.sslVerify=false -c http.version=HTTP/1.1 <命令>
```
